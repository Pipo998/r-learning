across() has three arguments:

.cols

First argument in across() - .cols selects columns to transform. Same specification as select(), i.e., can use starts_with() and ends_with().

Two additional selection techniques: everything() and where() -

set.seed(1014)

df <- tibble(
  grp = sample(2, 10, replace = TRUE),
  a = rnorm(10),
  b = rnorm(10),
  c = rnorm(10),
  d = rnorm(10)
)

df |>
  group_by(grp) |>
  summarize(across(everything(), median))
# A tibble: 2 × 5

1     1 -0.244 -0.522 -0.0974 -0.251 
2     2 -0.247  0.468  0.112   0.0700

where() - allows to select columns based on type:

  • where(is.numeric) - selects all numeric columns
  • where(is.character) - selects all string columns
  • where(is.Date) - selects all date columns
  • where(is.POSIXct) - selects all date-time columns
  • where(is.logical)- selects all logical columns

Can combine these with Boolean algebra, e.g., !where(is.numeric) or starts_with("a") & where(is.logical).

# Random permutation of NA values
rnorm_na <- function(n, n_na, mean = 0, sd = 1) {
  sample(x = c(
    rnorm(n - n_na, mean = mean, sd = sd),
    rep(x = NA, times = n_na)
  ))
}

Filtering

across() - great match for summarize() and mutate().

across() - awkward for filter() - dplyr provides two variants of across(): if_any() and if_all():

# Ex4: Explain what each step of the pipeline in this function does. What special feature of where() are we taking advantage of?
show_missing <- function(df, group_vars, summary_vars = everything()) {
  df |> 
    group_by(pick({{ group_vars }})) |> 
    summarize(
      across({{ summary_vars }}, \(x) sum(is.na(x))),
      .groups = "drop"
    ) |>
    select(where(\(x) any(x > 0)))
}

# group_by(pick({{ group_vars }})): groups the data by the specified variables.
# summarize(across(...)): for each group, counts the number of missing (NA) values in each selected summary column.
# select(where(\(x) any(x > 0))): removes columns that contain only zeros, keeping only columns that have at least one missing value in some group.
# Special feature of where() being used here is:
# where() allows to select columns based on a condition evaluated on the entire column, not just by their names or types.

Reading multiple files

purrr::map() - function for manipulating all files in a directory.

# Example - reading in directory full of excel spreadsheets
# Option1: read in individually:
data2019 <- readxl::read_excel("data/y2019.xlsx")
data2020 <- readxl::read_excel("data/y2020.xlsx")
data2021 <- readxl::read_excel("data/y2021.xlsx")
data2022 <- readxl::read_excel("data/y2022.xlsx")
# Then combine vie dplyr::bind_rows():
data <- bind_rows(data2019, data2020, data2021, data2022)

These kind of tasks require automation - three steps:

  1. list.files() - lists all files in a directory.
  2. Use purrr::map() - reads each of them into a list
  3. Use purrr::list_rbind() - combining them into single data frame

(Note: Approach not always possible, especially with increasing heterogeneity)

Listing files in directory

list.files() - three arguments: + path - directory to look in + pattern - regular expression used to filter file names - most common pattern: [.]xlsx$ or [.]csv$ to find all files with specific extensions + full.names determines whether or not directory name should be included in output - almost always want TRUE.

# Example: Using list.files()

Many simple iterations

Options: doing one single round of iterations, or, multiple rounds of iterations.

process_file <- function(path){
    df <- read_csv(path)
    
    df |>
       filter(!is.na(id)) |>
       mutate(id = tolower(id)) |>
       pivot_longer(jan:dec, names_to = "month")
}

paths |>
    map(process_file) |>
    list_rbind()

Alternatively, perform each step of process_file() to every file:

paths |>
    map(read_csv) |>
    map(\(df) df |> filter(!is.na(id))) |>
    map(\(df) df |> mutate(id = tolower(id))) |>
    map(\(df) df |> pivot_longer(jan:dec, names_to = "month")) |>
    list_rbind()

Or binding all together earlier:

paths |>

Writing to a database

Sometimes not possible to fit in data into memory - when working with a lot of files - cannot do map(files, read_csv). One approach - load data into database, access only bits needed with dbplyr.

Some data packages will contain a function that takes a vector of paths and loads them all into the database - case with duckdb_read_csv():

con <- DBI::dbConnect(duckdb::duckdb())
duckdb::duckdb_read_csv(conn = con, name = "gapminder", paths)

Helpful if we work with csv files - if we work with excel spreadsheets, need to do it by hand.

Start by creating a table that we fill in with data - create a template - a dummy data frame containing all columns we want, but only sampling of data:

template <- readxl::read_excel(paths[[1]])

# adding year
template$year <- 1952

Now use DBI::dbCreateTable() to turn template into database table:

# connecting to databse
con <- DBI::dbConnect(duckdb::duckdb())
