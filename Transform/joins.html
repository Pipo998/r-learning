Joins

R for Data Science (2e), Chapter 19

Introduction

Two important types of joins:

  • Mutating joins - i.e., adding new variables to one data frame from matching observations in another

  • Filtering joins - i.e., filtering observations from one data frame based on whether or not they match an observation in another.

  • Keys - i.e., variables connecting pair of data frames in a join

foreign key - variable/set of variables corresponding to primary key in another table:

  • flights$tailnum foreign key to primary key planes$tailnum

  • flights$carrier foreign key to primary key airlines$carrier

  • flights$origin foreign key to primary key airports$faa

  • flights$dest foreign key to primary key airports$faa

  • flights$dest foreign key to primary key airports$faa

  • flights$origin-flights$time_hour is compound foreign key to primary key weather$origin-weather$time_hour

Checking primary keys

How to verify that the “primary key” variable indeed uniquely identifies each observation?

Use count() on primary keys and and look for entries where n is greater than 1:

planes |>
  count(tailnum) |>
  filter(n > 1)
# A tibble: 0 × 2
# ℹ 2 variables: tailnum <chr>, n <int>
# tailnum indeed primary key

weather |>
  count(origin, time_hour) |>
  filter(n > 1)
# A tibble: 0 × 3
# ℹ 3 variables: origin <chr>, time_hour <dttm>, n <int>
# origin and time-hour indeed compound key

Also check for missing values - if there is a missing value it can NOT identify an observation!:

planes |>
  filter(is.na(tailnum))
# A tibble: 0 × 9
# ℹ 9 variables: tailnum <chr>, year <int>, type <chr>, manufacturer <chr>,
#   model <chr>, engines <int>, seats <int>, speed <int>, engine <chr>
weather |>
  filter(is.na(origin) | is.na(time_hour))

Basic joins

Six dplyr join functions:

  • left_join()
  • right_join()
  • inner_join()
  • full_join()
  • semi_join()
  • anti_join()

Syntax: Take pair of data frames (xandy) and return data frame. Order of rows and columns in output primarly determined by x.

Mutating joins

Mutating joins allow combining variables from two data frames - first matches observations by keys, then copies across variables from one data frame to the other (like mutate() joins add variables to the right):

  select(year, time_hour, origin, dest, tailnum, carrier)

How do joins work?

Focusing on how each row in x matches rows in y:

x <- tribble(
  ~key, ~val_x,
     1, "x1",
     2, "x2",
     3, "x3"
)
y <- tribble(
  ~key, ~val_y,
     1, "y1",
     2, "y2",
     4, "y3"
)

Inner-join: Rows retained if and only if the keys are equal!

inner_join(x, y)
Joining with `by = join_by(key)`
# A tibble: 2 × 3
    key val_x val_y
  <dbl> <chr> <chr>
1     1 x1    y1   
2     2 x2    y2

Outer-joins follow same principle:

Keep observations that appear in at least one of the data frames. Note: Syntax - *_join(x, y) Left-join: Keeps all observations in x - “matches” NA row in y, when there is no match.

Right-join: Keeps all observations in y - “matches” NA row in x, when there is no match.

Full join: Keeps all observations that appear in x and y, every row will be included - observations with no match, “match” with NA value.

Joins here are called equi joins, where rows match if the keys are equal.

### Row matching

Three possible outcomes for a row in x:

  • Doesn’t match anythingm it’s dropped
  • Matches 1 row in y, it’s preserved
  • Matches more than 1 row in y, it’s duplicated once for each match
# Example: matches more than 1 row in y
x <- tribble(
  ~key, ~val_x,
     1, "x1",
     2, "x2",
     3, "x3"
)
y <- tribble(
  ~key, ~val_y,
     1, "y1",
     2, "y2",
     2, "y3"
)

inner_join(x, y) # row is duplicated once for each match
Joining with `by = join_by(key)`
# A tibble: 3 × 3
    key val_x val_y
  <dbl> <chr> <chr>
1     1 x1    y1   
2     2 x2    y2   
3     2 x2    y3

### Filtering joins

Semi join keeps rows in x that have one or more matches in y

Anti join keeps rows in x that match zero rows in y

In both cases only existence of a match is important; doesn’t matter how many times it matches. Filtering join never duplicate rows like mutating joins do.

## Non-equi joins

Equi joins: Joins where the rows match if the x key equals the y key. As we move away from equi joins, will display keys as they will differ - dplyr keeps both keys with keep = TRUE.

x |> inner_join(y, join_by(key == key), keep = TRUE)
# A tibble: 3 × 4
  key.x val_x key.y val_y
  <dbl> <chr> <dbl> <chr>
1     1 x1        1 y1   
2     2 x2        2 y2   
3     2 x2        2 y3   
# Example: Non-equi join
# Match whenever x$key greater than or equal to y$key:
x |> inner_join(y, join_by(key >= key))
# A tibble: 7 × 4
  key.x val_x key.y val_y
  <dbl> <chr> <dbl> <chr>

2     2 x2        1 y1   
3     2 x2        2 y2   
4     2 x2        2 y3   
5     3 x3        1 y1   
6     3 x3        2 y2   
7     3 x3        2 y3

Four particular useful types of non-equi join:

Cross joins - match every pair of rows

Inequality joins - use <, <=, >, >= instead of ==

Rolling joins - similar to inequality joins but only find closest match

Overlap joins - special inequality join designed to work with ranges

Matches everything - useful when generating Cartesian product of rows - ouput has nrow(x) * nrow(y) rows - useful when generating permutations:

Use Overlapping joins

Overlap joins

Three helpers:

  • between(x, y_lower, y_upper) is short for x >= y_lower, x <= y_upper

  • within(x_lower, x_upper, y_lower, y_upper) is short for x_lower >= y_lower, x_upper <= y_upper.

  • overlaps(x_lower, x_upper, y_lower, y_upper) is short for x_lower <= y_upper, x_upper >= y_lower
