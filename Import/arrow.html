Arrow

R for Data Science (2e), Chapter 22

Introduction

Parquet format: open standards-based format used by big data systems.

Apache Arrow: Multi-language toolbox designed for efficient analysis and transport of large datasets - arrow package, provides dplyr backend, allowing analyzing larger-than-memory datasets using dplyr syntax.

Note

Arrow and dbplyr provide dplyr backend - depending if data is in database or in parquet files. Working with own data, requires either loading in database or converting in parquet file - can do both at first and decide which works best.

Don’t want to load lagre file into memory. File is 9GB, memory is 16GB - rule of thumb: We want at least twice as much memory as the size of data. This means we want to avoid read_csv() and use arrow::open_dataset():

seattle_csv <- open_dataset(
  sources = "data/seattle-library-checkouts.csv",
  col_types = schema(ISBN = string()),
  format = "csv"
)

What happens: open_dataset() scan only foirst thousand rows figuring out the structure of the dataset. Parquet format

Switch to parquet file format and split it up into multiple files.

Advantages of parquet

Parquet is used for rectangular data - it’s a custom binary format designed specifically for the needs of big data:

  • Parquet files usually smaller than CSV - relies on efficient encodings keeping file size down, and supports compression - making parquet files fast as there’s less data to move from disk to memory.

  • Rich type system - unlike CSV, parquet files store data in a way that records the type along with the data

  • Column-oriented - organized column-byy-column - leading to better performance for data analysis tasks compared to CSV files

  • Parqut files are chunked - can work on different part of the file at the same time - and skip chunks if lucky.

Partitioning

Useful to split large datasets across many files. Avoid size of partitioned files between 20MB and 2GB, and producing more than 10,000 files. Also try partitioning by variables that are filtered by - allowing arrow to skip work by reading only relevant files.

Rewriting the Seattle library data

Partitioning by CheckoutYear - since analysis will only look ar recent data - yieldd 18 chunks of reasonable size.

Define partitioning by dplyr::group_by(), save partitions to directory with arrow::write_dataset(). write_dataset() has two arguments: directory where file is created and format:

pq_path <- "data/seattle-library-checkouts"

seattle_csv |>
  group_by(CheckoutYear) |>
  write_dataset(path = pq_path, format = "parquet")

Takes time to run, but pays off making future operations faster:

Using dplyr with arrow

Need to read in parquet files again - use open_dataset(), this time with directory

Performance

seattle_csv |> 
  filter(CheckoutYear == 2021, MaterialType == "BOOK") |>
  group_by(CheckoutMonth) |>
  summarize(TotalCheckouts = sum(Checkouts)) |>
  arrange(desc(CheckoutMonth)) |>
  collect() |>
  system.time()
   user  system elapsed 
 16.929   1.917  16.307 
seattle_pq |>
  filter(CheckoutYear == 2021, MaterialType == "BOOK") |>
  group_by(CheckoutMonth) |>
  summarize(TotalCheckouts = sum(Checkouts)) |>
  arrange(desc(CheckoutMonth)) |>
  collect() |>
  system.time()
   user  system elapsed 
  0.264   0.030   0.073

  • Partitioning improves performance as query uses CheckoutYear == 2021 to filter data - arrow recognizes that it only needs to read 1 of 18 parquet files

  • Parquet format improves performance by storing data in binary form and having column-wise format, reading only the four columns used in the query (CheckoutYear, MaterialType, CheckoutMonth, and Checkouts).

This massive difference in performance is why it pays off to convert large CSVs to parquet!

Using duckdb with arrow

Other advantage of using parquet and arrow - can turn an arrow dataset into a DuckDB dataset by calling arrow::to_duckdb():

seattle_pq |>
  to_duckdb() |>
  filter(CheckoutYear >= 2018, MaterialType == "BOOK") |>
  group_by(CheckoutYear) |>
  summarize(TotalCheckouts = sum(Checkouts)) |>
  arrange(desc(CheckoutYear)) |>
  collect()
