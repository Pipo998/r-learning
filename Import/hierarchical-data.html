Hierarchical data

R for Data Science (2e), Chapter 23

Introduction

Data rectangling - taking data that is hierarchical, or tree-like, and converting it into rectangular data frame made up from rows and columns.

Two crucial functions:

  • tidyr::unnest_longer and tidyr::unnest_wider

Lists

simple vectors like integers, numbers, characters, date-times, and factors - homogeneous, i.e., every element is of the same data type.

Lists \(\rightarrow\) stores elements of different types in the same vector - created by list().

x1 <- list(1:4, "a", TRUE)
x1
[[1]]
[1] 1 2 3 4

[[2]]
[1] "a"

[[3]]
[1] TRUE

x2 <- list(a = 1:2, b = 1:3, c = 1:4)
x2
$a
[1] 1 2

$b
[1] 1 2 3

$c
[1] 1 2 3 4

Hierarchy

x3 <- list(list(1, 2), list(3, 4))
x3
str(x3)

x4 <- c(list(1, 2), list(3, 4))
x4

x5 <- list(1, list(2, list(4, list(4, list(5)))))

List-columns

Lists can live within tibbles - list-columns.

USeful when placing objects in tibbles usually not belonging in there - used in tidymodels storing things liek model output or resamples in data frame.

df <- tibble(
  x = 1:2,
  y = c("a", "b"),
  z = list(list(1, 2 ), list(3, 4, 5))
)

df
# A tibble: 2 × 3
      x y     z         
  <int> <chr> <list>    
1     1 a     <list [2]>
2     2 b     <list [3]>
# Column-lists still behave like any other column:
df |>
  filter(x == 1)
# A tibble: 1 × 3
      x y     z         
  <int> <chr> <list>    
1     1 a     <list [2]>

Unnesting

Turning column-lists back into regular rows and columns - usually two basic forms of list-columns: named and unnamed

# Named list-columns:
# Usually same name in every row
# Unnesting - each named element becomes new named column
df1 <- tribble(
  ~x, ~y,
  1, list(a = 11, b = 12),
  2, list(a = 21, b = 22),
  3, list(a = 31, b = 32),
)

# Unnamed list-columns:
# Number of elements tend to vary from row-to-row
# Unnesting - unnest into rows - one row per observation
df2 <- tribble(
  ~x, ~y,
  1, list(11, 12, 13),
  2, list(21),
  3, list(31, 32),
)

Two functions for these two cases: unnest_wider() and unnest_longer()

unnest_wider()

Each row has same number of elements with the same names - put each component into own column with unnest_wider():

  • names of new columns come from names of the list elements - can also use names_sep argument to distinguish column x from y:
df1 |>
  unnest_wider(col = y)
# A tibble: 3 × 3
      x     a     b
  <dbl> <dbl> <dbl>
1     1    11    12
2     2    21    22
3     3    31    32
# Using names_sep():
df1 |>
  unnest_wider(col = y, names_sep = "_") # avoiding ambiguating by repeating names
# A tibble: 3 × 3
      x   y_a   y_b
  <dbl> <dbl> <dbl>
1     1    11    12
2     2    21    22
3     3    31    32

unnest_longer

Each row contains an unnamed list - almost natural to put elements into its own row with unnest_longer():

df2 |>
  unnest_longer(col = y)
# A tibble: 6 × 2
      x     y
  <dbl> <dbl>
1     1    11
2     1    12
3     1    13
4     2    21
5     3    31
6     3    32

Note, x is duplicated for each element inside of y - one row of output for each element inside the list-column:

df6 <- tribble(
  ~x, ~y,
  "a", list(1, 2),
  "b", list(3),
  "c", list()
)

df6 |>
  unnest_longer(col = y) # Row disappears when element is empty
# A tibble: 3 × 2
  x         y
  <chr> <dbl>
1 a         1
2 a         2
3 b         3
# Can keep empty element by keep_empty = TRUE
df6 |>
  unnest_longer(col = y, keep_empty = TRUE)
# A tibble: 4 × 2
  x         y
  <chr> <dbl>
1 a         1
2 a         2
3 b         3
4 c        NA

Inconsistent types

Unnesting list-columns containing different types of vector:

df4 <- tribble(
  ~x, ~y,
  "a", list(1),
  "b", list("a", TRUE, 5)
)

df4 |>
  unnest_longer(y)
# A tibble: 4 × 2
  x     y        
  <chr> <list>   
1 a     <dbl [1]>
2 b     <chr [1]>
3 b     <lgl [1]>
4 b     <dbl [1]>

Output contains a list-column - every element of the list-column contains a single element - unnest_longer() can’t find common typeof vector, thus keeps original in a list-column. Note: Every element in this column is a list, even though contents of different types. See chapter 26 for dealing with inconsistent types.

Other functions

  • unnest_auto(): automatically picks between unnest_longer() and unnest_wider()

  • unnest(): unnests both rows and columns - useful with list-column containing 2d structure like a data frame.

JSON

JSON (JavaScript Object Notation) is the standard format used by most web APIs to exchange data. It maps closely to R objects, although there is no perfect 1-to-1 correspondence.

JSON data types

  • null → NA
  • String → character
  • Number → numeric/integer (Inf, -Inf, and NaN are not supported)
  • Boolean → TRUE / FALSE (true / false in JSON)
  • Array ([]) → unnamed list in R
  • Object ({}) → named list in R
Note

JSON has no native date or datetime type. Dates are usually stored as character strings and should be converted using readr::parse_date() or readr::parse_datetime().

jsonlite

The jsonlite package provides two main functions for working with JSON:

  • read_json() – reads a JSON file from disk.
  • parse_json() – parses a JSON string into R objects.

fromJSON() is another commonly used function, but it automatically simplifies nested structures (simplifyVector = TRUE). For learning how to work with nested data, parse_json() is preferred because it preserves the original structure.

library(jsonlite)

# Scalar
str(parse_json("1"))
 int 1
# Array -> unnamed list
str(parse_json("[1, 2, 3]"))
List of 3
 $ : int 1
 $ : int 2
 $ : int 3
# Object -> named list
str(parse_json('{"x": [1, 2, 3]}'))
List of 1
 $ x:List of 3
  ..$ : int 1
  ..$ : int 2
  ..$ : int 3

Top-level JSON structures

1. Top-level array

Each element represents an observation.

json <- '[
  {"name": "John", "age": 34},
  {"name": "Susan", "age": 27}
]'

tibble(json = parse_json(json))
# A tibble: 2 × 1
  json            
  <list>          
1 <named list [2]>
2 <named list [2]>

Result:

  • 2 rows
  • each row is one observation stored as a named list

2. Top-level object

The entire JSON is one object that contains other fields.

Since parse_json() returns a single named list, wrap it in list() before creating a tibble:

json <- '{
  "status": "OK", 
  "results": [
    {"name": "John", "age": 34},
    {"name": "Susan", "age": 27}
 ]
}
'

tibble(json = list(parse_json(json)))
# A tibble: 1 × 1
  json            
  <list>          
1 <named list [2]>

This creates a tibble with one row, where the JSON object is stored in a single list-column.

Rectangling nested JSON

A typical workflow is:

  1. Parse the JSON using parse_json().
  2. Determine whether the top level is an array or an object.
  3. Explore the structure using unnest_longer() and unnest_wider().
  4. Once the path to the desired component is known, use hoist() to extract it directly.
  5. Convert character variables (e.g., dates or numbers) to their appropriate R types if necessary.

Common tidyr functions

Function Purpose
unnest_longer() Turns list elements into rows (for arrays).
unnest_wider() Turns named list elements into columns (for objects).
hoist() Extracts specific nested components without unnesting everything.
Tip

Rule of thumb

  • Array ([]) → use unnest_longer()
  • Object ({}) → use unnest_wider()
  • Known path to a nested value → use hoist()

Starting the rectangling process

When working with JSON, the first step depends on the top-level structure.

Case 1: Top-level array ([])

A top-level array usually represents multiple observations. After parsing, each element becomes one row of a tibble.

json <- '[
  {"name": "John", "age": 34},
  {"name": "Susan", "age": 27}
]'

df <- tibble(json = parse_json(json))

df
# A tibble: 2 × 1
  json            
  <list>          
1 <named list [2]>
2 <named list [2]>

Expand each named list into columns:

df |>
  unnest_wider(json)
# A tibble: 2 × 2
  name    age
  <chr> <int>
1 John     34
2 Susan    27

Result:

  • Each JSON object becomes one row.
  • unnest_wider() extracts the fields (name, age) into columns.

Case 2: Top-level object ({})

Sometimes the entire JSON is a single object containing metadata and the actual data.

json <- '{
  "status": "OK",
  "results": [
    {"name": "John", "age": 34},
    {"name": "Susan", "age": 27}
  ]
}'

df <- tibble(json = list(parse_json(json)))

df
# A tibble: 1 × 1
  json            
  <list>          
1 <named list [2]>

Since the parsed JSON is one named list, wrap it in list() before creating the tibble.

Extract the nested observations:

json <- '{
  "status": "OK",
  "results": [
    {"name": "John", "age": 34},
    {"name": "Susan", "age": 27}
  ]
}'


df |>
  unnest_wider(json) |>
  unnest_longer(results) |>
  unnest_wider(results)
# A tibble: 2 × 3
  status name    age
  <chr>  <chr> <int>
1 OK     John     34
2 OK     Susan    27

Result:

  • status is repeated for each observation.
  • results is an array, so unnest_longer() creates one row per element.
  • Each result is a named list, so unnest_wider() converts its fields into columns.

Extract only the component you need

If you’re only interested in a nested component, you can access it directly before creating the tibble:

json <- '{
  "status": "OK",
  "results": [
    {"name": "John", "age": 34},
    {"name": "Susan", "age": 27}
  ]
}'


df <- tibble(results = parse_json(json)$results)

df |>
  unnest_wider(results)
# A tibble: 2 × 2
  name    age
  <chr> <int>
1 John     34
2 Susan    27

This avoids carrying along unnecessary metadata (e.g., status) and is often the cleanest approach.

Tip

Rule of thumb

  • Top-level array ([]) → tibble(json = parse_json(json))
  • Top-level object ({}) → tibble(json = list(parse_json(json)))
  • If you only need one nested component, extract it first (e.g. parse_json(json)$results).
