Database basics

Simplest level - Database as collection of data frames, .i.e., tables. Database table is collection of named columns - every value in column is same type.

Differences:

  • Databases stored on disk - can be arbitrarly large. Data frames stored in memory and are limited.

  • Database tables almost always have indexes unlike data frames and tibbles.

  • Classical databases optimized for data collection - row-orientend database. Column-orieneted databases make analyzing existing data much faster

Databases are run by database management systems( DBMS ); Three forms:

  • Client-server: Powerful central server; Useful for haring within organization - e.g., PostgreSQL, SQL Server, Oracle, etc.

  • Cloud: e.g., Snowflake, Amazon’s RedShift, Google’s BigQuery run in cloud - useful for handling extremely large datasets/ more computing resources

  • In-process: e.g., SQLite, duckdb, run on computer - useful wehn working with large datasets where you’re the primary user.

Connecting to a database

Connecting from R requires pair of packages:

  • DBI (database interface) - provides generic functions that connect to database, uplaod data, runSQL queries, etc.

  • Package for DBMS - translates generic DBI commands into specifics needed for given DBMS - usually one package for each DBMS, e.g., RPostgres for PostgreSQL, etc.

Creat database connection using DBI::dbConnect(): + first argument selects DBMS + second/subsequent argument describes how to connect to it

 con <- DBI::dbConnect(   
  RMariaDB::MariaDB(),
  username = "foo"
)

con <- DBI::dbConnect(
  RPostgresDB:: Postgres(),
  hostname = "database.mycompany.com",
  port = 1234
)

For specifics ask DBA (database administrator) in the team.

SQL Basics

Top-level components of SQL called statements:

  • CREATE for defining new tables
  • INSERT for adding data
  • SELECT for retrieving data - also called queries

Query is made up of clauses: Five important clauses: SELECT, FROM, WHERE, ORDER BY, and GROUP BY.

Every query must have SELECT and FROM clauses - e.g., simple query SELECT * FROM table - selects allscolumns from table:

flights |> show_query()
<SQL>
SELECT *
FROM flights
planes |> show_query()
<SQL>
SELECT *
FROM planes
# WHERE controls which rows are included
# ORDER BY how they are ordered

flights |>
  filter(dest == "IAH") |>
  arrange(dep_delay) |>
  show_query()
<SQL>
SELECT *
FROM flights
WHERE (dest = 'IAH')
ORDER BY dep_delay
# GROUP BY converts query to summary, causing aggregation:
flights |>
  group_by(dest) |>
  summarize(dep_delay = mean(dep_delay, na.rm = TRUE)) |>
  show_query()
<SQL>
SELECT dest, AVG(dep_delay) AS dep_delay
FROM flights
GROUP BY dest

In SQL order matters: SELECT, FROM, WHERE, GROUP BY, ORDER BY. BUT order of evaluation: FROM, WHERE, GROUP BY, SELECT, ORDER BY.

SELECT

SELECT performs same job as select(), mutate(), rename(), relocate(), summarize().

Renaming in SQL is called aliasing and is done via AS - new name on the right NOT on the left.

planes |>
  select(tailnum, type, manufacturer, model, year) |>
  show_query()
<SQL>
SELECT tailnum, "type", manufacturer, model, "year"
FROM planes
planes |>
  select(tailnum, type, manufacturer, model, year) |>
  rename(year_built = year) |>
  show_query()
<SQL>
SELECT tailnum, "type", manufacturer, model, "year" AS year_built
FROM planes
planes |>
  select(tailnum, type, manufacturer, model, year) |>
  relocate(manufacturer, model, .before = type) |>
  show_query()
<SQL>
SELECT tailnum, manufacturer, model, "type", "year"
FROM planes
flights |>
  mutate(
    speed = distance / (air_time / 60)
  ) |>
  show_query()
<SQL>
SELECT *, distance / (air_time / 60.0) AS speed
FROM flights

FROM

FROM clause defines the data source.

GROUP BY

group_by() translates to GROUP BY clause; summarize() translates to SELECT:

diamonds_db |>
  group_by(cut) |>
  summarize(
    n = n(),
    avg_price = mean(price, na.rm = TRUE)
  ) |>
  show_query()
<SQL>
SELECT cut, COUNT(*) AS n, AVG(price) AS avg_price
FROM diamonds
GROUP BY cut

WHERE

filter() is translated to WHERE clause:

flights |>
  filter(dest == "IAH" | dest == "HOU") |>
  show_query()
<SQL>
SELECT *
FROM flights
WHERE (dest = 'IAH' OR dest = 'HOU')
flights |>
  filter(arr_delay > 0 & arr_delay < 20) |>
  show_query()
<SQL>
SELECT *
FROM flights
WHERE (arr_delay > 0.0 AND arr_delay < 20.0)
  • | becomes OR and & becomes AND.
  • SQL uses = for comparison, not ==.
  • SQL uses only '' for strings, not "".
  • SQL uses IN which is close to R’s %in%
flights |> 
  filter(dest %in% c("IAH", "HOU")) |>
  show_query()
<SQL>
SELECT *
FROM flights
WHERE (dest IN ('IAH', 'HOU'))

Variables that are created using summarize, when filtering, will need HAVING clause in SQL, rather than WHERE:

diamonds_db |>
  group_by(cut) |>
  summarize(n = n()) |>
  filter(n > 100) |>
  show_query()
<SQL>
SELECT cut, COUNT(*) AS n
FROM diamonds
GROUP BY cut
HAVING (COUNT(*) > 100.0)

ORDER BY

arrange() is translated to ORDER BY clause:

flights |>
  arrange(year, month, day, desc(dep_delay)) |>
  show_query()
<SQL>
SELECT *
FROM flights
ORDER BY "year", "month", "day", dep_delay DESC

Subqueries

Subsquery is a query used as a data source in the FROM clause - sometimes dbplyr uses subqueries working around limitations of SQL.

# Expressions in SELECT call cannot refer to column just created

flights |>
  mutate(
    year1 = year + 1,
    year2 = year1 + 1
  ) |>
  show_query()
<SQL>
SELECT *, year1 + 1.0 AS year2
FROM (
  SELECT *, "year" + 1.0 AS year1
  FROM flights
) AS q01

Joins

SQL are similar to dplyr joins:

flights |>
  left_join(planes |> rename(year_built = year), join_by(tailnum)) |>
  show_query()
<SQL>
SELECT
  flights.*,
  planes."year" AS year_built,
  "type",
  manufacturer,
  model,
  engines,
  seats,
  speed,
  engine
FROM flights
LEFT JOIN planes
  ON (flights.tailnum = planes.tailnum)

SQL Joins: SELECT flights.*, “type”, manufacturer, model, engines, seats, speed FROM flights INNER JOIN planes ON (flights.tailnum = planes.tailnum)

SELECT flights.*, “type”, manufacturer, model, engines, seats, speed FROM flights RIGHT JOIN planes ON (flights.tailnum = planes.tailnum)

SELECT flights.*, “type”, manufacturer, model, engines, seats, speed FROM flights FULL JOIN planes ON (flights.tailnum = planes.tailnum)
