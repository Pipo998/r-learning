Web Scraping

R for Data Science (2e), Chapter 24

Introduction

Basics of web scraping with rvest - extracting data from web pages. Some pages offer API, set of structured HTTP requests that return data as JSON (See chapter 23). Scraping works whether or not site provides an API.

Scraping ethics and legalities

Legalities depends on where you live. If the data is public, non-personal, and factual - likely to be ok.

If the data isn’t public, non-personal, or factual or you’re scraping the data specifically to make money with it - need to talk to a lawyer.

Terms of service

  • Many websites include Terms of Service (ToS) that may prohibit web scraping.
  • Companies often make broad legal claims, so these terms should be read critically.
  • In the US:
    • Simply posting ToS on a website is usually not enough to legally bind users.
    • Users are generally bound only after an explicit action, such as creating an account or accepting the terms.
    • Publicly accessible data (no account required) is therefore less likely to be subject to binding ToS.
  • In Europe:
    • Courts have been more willing to enforce ToS, even without explicit user agreement.
  • When scraping, always consider both the website’s ToS and the legal jurisdiction.

Personally identifiable information

  • Be very cautious when scraping personally identifiable information (PII) (e.g., names, emails, phone numbers, birth dates).
  • GDPR and other privacy laws, especially in Europe, impose strict rules on collecting and storing personal data.
  • Publicly available data is not automatically ethical or legal to scrape and publish.
  • Example: Researchers released public OkCupid user data without anonymization, leading to widespread ethical criticism.
  • If scraping PII, ensure compliance with privacy laws and follow ethical research practices, including anonymization where appropriate.

Copyright

  • Facts are generally not protected by copyright, so scraping factual data is usually permissible.
  • Original creative works (e.g., text, images, books, music) are protected by copyright.
  • Europe additionally protects databases through a separate database (“sui generis”) right.
  • Example: A recipe’s ingredients and instructions are not copyrightable, but accompanying original text is.
  • Fair use may allow limited scraping of copyrighted content, especially for research or non-commercial purposes, if only the necessary content is collected.

HTML basics

HTML - HyperText Markup Language - describes web pages.

<html>
<head>
  <title>Page title</title>
</head>
<body>
  <h1 id='first'>A heading</h1>
  <p>Some text &amp; <b>some bold text.</b></p>
  <img src='myimg.png' width='100' height='100'>
</body>

Hierarchical structure - formed by elements: Consist of start tag (e.g., <tag>), optional attributes (ìd='first'), an end tag (like </tag>), contents (everything in between the start and end tag).

Can’t write directly < and > directly - use HTML escapes &gt (greater than) and &lt (less than) - use &amp for literal &.

Elements

Most important:

  • HTML page must be in

    element, and must have two components:

    • contains document metadata, e.g., page title, and

      • contains content seen in the browser.

  • Block tags - e.g.,

    (heading 1),

    (section),

    (paragraph),

      (ordered list) form overall structure of the page.

    1. Inline tags - (bold), (italics), (link) format text inside block tags.

See HTML guides: MDN Web Docs

Most elements can have content in between start and end tags - content can either be text or more elements (children are the elements it contains, <p> element has one child, the <b> element):

<p>
  Hi! My <b>name</b> is Hadley.
</p>

Attributes

  • HTML tags can contain attributes (e.g., id, class, href, src) that provide additional information.
  • id and class are commonly used for CSS styling and are useful for selecting elements when scraping.
  • href stores the destination URL of links (<a> tags).
  • src stores the source URL of embedded resources, such as images (<img> tags).

Extracting data now requires CSS selectors - allow to identify elements of interest - and rvest functions used to extract data from them. HTML tables have special tools.

Find elements

CSS - cascading style sheets - tool to define visual styling of HTML docs.

CSS selectors - language for selecting elements on a page. \(\rightarrow\) define patterns for locating HTML elements.

Most important: + p selects all <p> elements. + .title selects all elements with class “title”. + #title selects id elements equaling “title” - unique, thus only one element will be selected.

html <- minimal_html("
  <h1>This is a heading</h1>
  <p id='first'>This is a paragraph</p>
  <p class='important'>This is an important paragraph</p>
")

# use html_elements() to find all elements that match the selector:
html |> html_elements("p")
{xml_nodeset (2)}
[1] <p id="first">This is a paragraph</p>
[2] <p class="important">This is an important paragraph</p>
html |> html_elements(".important")
{xml_nodeset (1)}
[1] <p class="important">This is an important paragraph</p>
html |> html_elements("#first")
{xml_nodeset (1)}
[1] <p id="first">This is a paragraph</p>

html_element() - returns same number of outputs as input - applied to whole document will return first match:

html |> html_element("p")
{html_node}
<p id="first">

Selector that doesn’t match any elements: + html_element() - returns missing value + html_elements() - returns vector of length 0

html |> html_element("b")
{xml_missing}
<NA>
html |> html_elements("b")
{xml_nodeset (0)}

Nesting selections

In most cases, use html_elements() and html_element() together - using html_elements() to identify elements that will become observations then using html_element() to find elements that will become variables.

Text and attributes

After selecting elements of interest - need to extract data, either from text contents or some attributes.

html_text2() - extracts plain text contents of HTML element:

characters |> 
  html_element("b") |>
  html_text2()
[1] "C-3PO"  "R4-P17" "R2-D2"  "Yoda"  
characters |> 
  html_element(".weight") |>
  html_text2()
[1] "167 kg" NA       "96 kg"  "66 kg"

html_attr() - extracts data from attributes - always returns string:

html <- minimal_html("
  <p><a href='https://en.wikipedia.org/wiki/Cat'>cats</a></p>
  <p><a href='https://en.wikipedia.org/wiki/Dog'>dogs</a></p>
")

html |> 
  html_elements("p") |> 
  html_element("a") |> 
  html_attr("href")
[1] "https://en.wikipedia.org/wiki/Cat" "https://en.wikipedia.org/wiki/Dog"

Tables

HTML tables are built up from four main elements: <table>, <tr> (table row), <th> (table heading), and <td> (table data):

html <- minimal_html("
  <table class='mytable'>
    <tr><th>x</th>   <th>y</th></tr>
    <tr><td>1.5</td> <td>2.7</td></tr>
    <tr><td>4.9</td> <td>1.3</td></tr>
    <tr><td>7.2</td> <td>8.1</td></tr>
  </table>
  ")

# Can use html_table():
html |>
  html_element(".mytable") |>
  html_table() # x and y automatically convert to numbers; optional arg: convert = FALSE
# A tibble: 3 × 2
      x     y
  <dbl> <dbl>
1   1.5   2.7
2   4.9   1.3
3   7.2   8.1

Finding right selector

  • Finding the correct CSS selector often requires trial and error—it should be specific enough to exclude unwanted elements while broad enough to capture all desired ones.
  • Useful tools:
    • SelectorGadget: Automatically suggests CSS selectors based on selected examples.
    • Browser Developer Tools (Inspect): Explore the HTML structure, especially id and class attributes.
  • In Chrome DevTools, you can right-click an element → Copy → Copy selector to obtain a unique CSS selector.
  • If you want to better understand CSS selectors, use resources such as Selectors Explained, CSS Diner, and the MDN Web Docs.

Star Wars

Simple example in vignette("starwars"). Each movie shares same structure:

Dynamic websites

  • html_elements() works only on the raw HTML downloaded from a website.
  • Many modern websites generate content dynamically using JavaScript, so the desired elements may not appear in the raw HTML.
  • Therefore, html_elements() may return nothing even though the content is visible in the browser.
  • To scrape dynamic sites, JavaScript must be executed by simulating a real browser.
  • rvest is adding support for this using the chromote package, which controls a Chrome browser in the background and allows interaction (e.g., clicking buttons, typing text).
